## Files

### New: `docs/adr/` (continue from existing `0001-preemptible-kernel-is-a-non-goal.md`)

Architectural set first, then conventions. Format: `docs/adr/000N-slug.md`,
short title + 1–3 sentence decision paragraph (plus optional
Considered/Consequences only where they earn their place). No status
frontmatter (all accepted, nothing superseded yet). License header on each
file: `GPL-2.0-or-later` + `SPDX-FileCopyrightText` for the contributor,
matching the root docs style of `0001`.

**`0002-full-gnu-hurd-support-defines-mach-abi-compatibility.md`**
100% Mach ABI compatibility with GNU Mach is the goal. The ABI surface is
whatever a stock GNU Hurd userland observes: trap numbers, argument/return
register conventions, `mach_msg` header and message layouts, type sizes as
seen from userspace — plus MIG: stubs compiled against GNU Mach headers must
work against this kernel without regeneration. Compatibility is proven by the
frozen `abi-test/` suite passing and a stock GNU Hurd userland booting and
running. Kernel-internal Rust representation is free except where MIG stub
compatibility pins it.

**`0003-x86-64-is-the-only-target-for-now.md`**
x86_64 is the sole supported target *for now*, to keep the port tractable — a
deliberate deferral, not an identity boundary. No multi-arch work until the
x86_64 port is solid; a future aarch64/riscv port is not planned and is not
blocked by this decision. x86_32 / 32-bit compat is rejected as a dead
architecture and will not be supported.

**`0004-rust-is-the-implementation-language.md`**
Rust is the implementation language. `cargo build` alone produces the final
kernel ELF: no separate assembler/linker step, no build system beyond Cargo;
linker is `rust-lld`, not GNU `ld`. Prefer official prebuilt Rust targets
(`x86_64-unknown-none`); a custom target JSON / `-Z build-std` only if no
official target covers the architecture. Hand-written C code (`.c`/`.S`
bodies) and checked-in generated C are forbidden. MIG output is generated at
build time into `OUT_DIR` and never checked in. *Exception recorded as debt:*
hand-written C **headers** at the MIG/FFI seam
(`crates/mach-mig-sys/mig/include/`) are tolerated today; they are declarations
only and should shrink over time. Inline assembly is covered by ADR 0007.

**`0005-unsafe-is-allowed-but-must-be-justified.md`**
`unsafe` is allowed but is not the best choice. Safe abstractions are the
default; `unsafe` is permitted where the kernel genuinely needs it (FFI, raw
pointers, inline asm, `ptr::write` of born-whole objects) and discouraged in
ordinary logic. Every `unsafe` use carries a written contract (`# Safety` on
`unsafe fn`, `// SAFETY:` naming the actual lock or precondition). No crate
sets `#![forbid(unsafe_code)]`. The *mechanics* of the comment contract live
here as the rule; AGENTS.md keeps only a pointer. Rationale: a kernel cannot
ban `unsafe` without forcing worse abstractions at the hardware boundary — the
discipline is the comment contract and review, not prohibition.

**`0006-portable-subsystems-are-modularized-behind-a-platform-trait.md`**
Standing design principle. Portable subsystems live in their own workspace
crate (`crates/lock`, `crates/clock`, `crates/collections`) with zero arch
imports; every machine- or kernel-specific service arrives through a small
`Platform` trait — a zero-sized type parameter (lock) or a stored value over
composed traits (clock: `TimeCounter + Critical + Calendar + TimePage`).
Flavours are generated by macros over one backend; debug/test fakes and loom
runs use `cfg`, not Cargo features. Established pattern: `crates/lock` and
`crates/clock` (see their crate-level ADRs under `crates/*/docs/adr/`, which
stay crate-local). New subsystems follow this silently; only a *deviation*
needs a new ADR.

**`0007-inline-assembly-only.md`**
Assembly is written inline via `core::arch::asm!` / `global_asm!` /
`naked_asm!` with `options(att_syntax)`. No separate `.s`/`.S` files. Keeps
the toolchain story Cargo-only (see ADR 0004).

**`0008-architecture-names-are-x86-and-x86-64.md`**
In file names, target names, and prose, 32-bit is `x86` and 64-bit is
`x86_64`. Never `i386`, `i686`, `amd64`. Exception: toolchain-defined
identifiers (target triples, ELF format names) keep the toolchain spelling.

**`0009-intrusive-collection-objects-are-born-whole.md`**
Objects in intrusive collections are born whole: one struct literal (with
`Link::new()`), `ptr::write`n into fresh storage. Never stamp fields over
recycled or zeroed memory. (Cross-ref `crates/collections`.)

**`0010-spdx-headers-and-provenance.md`**
Every source file starts with an SPDX license line and one
`SPDX-FileCopyrightText` per holder — never a `Copyright (c)` comment. A file
derived from existing code keeps the upstream license and carries a provenance
block after a blank comment line: upstream holders first, contributor last,
then `Derived from <project> (commit …)` + `original files:`. Default license
for new files is `GPL-2.0-or-later`. Non-copyrightable files are exempt.
License texts live in `LICENCES/`. Consolidates the licensing blocks currently
split across CONTRIBUTING and AGENTS.md (include the two header templates in
this ADR — they are the rule text now).

**`0011-ai-assisted-contributions.md`**
Pure lift of CONTRIBUTING's five points: (a) tooling legal compatibility — the
tool's terms must not conflict with distribution/modification/use of its
output here; (b) licensing/attribution — verify third-party material; SPDX
headers remain the contributor's job; (c) accountability — the committer is
accountable for the whole contribution and must understand every change and
justify it in review; (d) disclosure encouraged via `Assisted-By:` trailer;
(e) bulk/autonomous changes discussed first and human-overseen. No new policy.
