# Investigation: Matt Pocock skills vs. the web skill landscape

Research only — no code changes. Sources: local skill trees, `skills.sh`
leaderboard/official packs, and the GitHub repos for the main collections
(fetched 2026-06 in this session).

## Short answer

**Matt Pocock is not "the best" overall — he is the best *engineering
process* set if you want composable skills you own and hack.** Rivals beat
him on stars, domain knowledge, and rigid full-methodology automation.

| Criterion | Winner |
| --- | --- |
| Engineering process (grill → spec → tickets → implement → review) | **mattpocock/skills** |
| Stars / popularity of a full methodology | **obra/superpowers** (293k vs Matt's 273k) |
| Official reference + document skills | **anthropics/skills** (179k) |
| Frontend / React / Next.js / design taste | **vercel-labs/agent-skills** + taste/design packs |
| Vendor product expertise | skills.sh **Official** catalog (AWS, Azure, Prisma, …) |
| Process-owning SDD toolkit | **github/spec-kit** (139k) |

## Matt Pocock — strengths and gaps

**Strengths (why he feels "best" for real engineering):**

1. **Composable, not process-owning.** Explicit anti-GSD/BMAD/Spec-Kit
   stance: small skills you adapt. Easier to debug when the process breaks.
2. **Coherent main flow** via `ask-matt`: grill → (prototype) → spec →
   tickets → implement/TDD/code-review → retro. Few packs have a router
   this clean.
3. **Domain modeling is distinctive**: `GLOSSARY.md` + ADRs from
   `grill-with-docs` / `domain-modeling`. Most rivals skip shared language.
4. **User-invoked vs model-invoked** split is well designed.
5. **Adoption**: 273k stars, 54 skills, 25.3M installs; `grill-me` alone
   1.3M. Strongest single-skill install numbers in the process category.
6. **You already have it** and it's wired for this repo style (issue
   tracker config, triage labels, domain docs).

**Gaps (where others win):**

| Need | Better source |
| --- | --- |
| React/Next.js/Vercel perf & UI rules | `vercel-labs/agent-skills` (react-best-practices, web-design-guidelines) |
| Document generation (docx/pdf/xlsx/pptx) | `anthropics/skills` / your MiMoCode builtins |
| Visual design taste | `leonxlnx/taste-skill`, `anthropics/skills/frontend-design` |
| Cloud / platform products | Official packs: `microsoft/azure-skills`, AWS, Prisma, Supabase, Cloudflare… |
| One rigid "just run the methodology" | `obra/superpowers` (brainstorm → plan → subagent TDD) or `github/spec-kit` |
| Media (video/image/music) | `genmedia-labs/skills`, `prime-skills/runcomfy-agent-skills` |
| Research rigor packs | `lllllllama/rigorpilot-skills` |

## Verdict for this setup

You already sit on the strongest *engineering-process* stack (Matt) plus a
strong *host toolkit* (MiMoCode builtins). Remaining gaps worth filling only
if you hit them:

1. **Frontend/UI work** → add `vercel-labs/agent-skills` (React/Next) and/or
   a taste/design pack.
2. **Vendor APIs** → pick the official pack when you touch that product
   (Azure, Prisma, …).
3. **Prefer a rigid methodology** → try `obra/superpowers` or `github/spec-kit`
   instead of (not on top of) Matt's flow — they will fight each other.

No install/changes recommended right now unless you want one of the gap
fills above.
